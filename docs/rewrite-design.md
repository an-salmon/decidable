# Typed exact checks and certificate search

Design for the public proof-checking-core baseline at b9720b97e8fdb68a18eb31679da2fea25ddc1fa1. The deliverable is an additive Python 3.9+ library rewrite around the existing exact mathematics routines. Existing imports, Boolean contracts, accepted domains, and report tests remain supported. SymPy supplies exact polynomial arithmetic. Numerical solvers remain optional.

## Who supplies each part of a claim?

The caller chooses dimension, parameters, hypotheses and scope, and justifies the passage from their mathematical model to the finite input. The package accepts a typed Python value, checks its domain, and normalizes it to exact rationals, polynomials, matrices, words or a rational generating function. A reduction records the assumptions and identity that link the target to the next check. Dispatch uses the declared fragment and operation. A checker either runs a decision procedure in its stated domain or replays a witness. Search may propose a witness using exact enumeration or an optional numerical solver. Only exact replay certifies the claim.

For example, a modal inequality can reduce to a scalar inequality when an external argument supplies nonnegative modal weights and the scalar bound holds for every allowed mode. An identity for a finite sample of eigenvalues has exactly that sample as its scope. The checker does not derive positivity of the weights, completeness of a spectral representation, convergence of an infinite expansion, or the original analytic model.

## Shared contract

Use the stable input fragment IDs rational, noncommutative, gram, polynomial, linear, series and linalg. Retain old tier names in historical documentation as needed. Fragment metadata names the mathematical input and lists independently named operations, including computation, decision, reduction, certificate verification and bounded search. New specialized operations can live under existing fragments. Public Python entry points accept typed domain objects directly. The small explicit dispatcher must reject an unknown operation or incompatible domain and must never guess an analytic interpretation from a string. No universal expression language or opaque callback that can assert its own exactness is needed for dispatch.

Publish CheckResult from report.py with keyword fields status, scope, reason and witness (optional). Status is a string from verified, disproved, unsupported, inconclusive, numerical_evidence. Scope is explicit human-readable text. A finite exact outcome reports its finite set, degree or range. A witness can be a concrete assignment, index, rational vector, multiplier sequence or certificate object. A failed certificate or exhausted search yields inconclusive. A counterexample must violate the original typed claim. A complete decision can disprove the claim within its documented interpretation. Unsupported input and malformed input follow the documented boundary of the entry point. Legacy exceptions remain available from original APIs. Never infer disproof from a legacy Boolean False without its operation semantics. Numeric, scoped and composite obligations must preserve evidence strength and scope through dependencies. Legacy Boolean presentation may be retained alongside richer results.

## Independently owned implementation milestones

Files below are in src/decidable unless specified. Each stream owns its new tests. The integration owner controls package exports, README and shared report contracts. Calls between streams should use module-level imports so no feature waits for re-exports.

### A. Fragment contracts, dispatch and reporting

Own fragments.py, report.py, __init__.py, README and integration tests. Implement FragmentSpec and CheckResult. Give each dispatched operation a documented public function and guarantee. Preserve the established Report and Obligation call sites, including numeric/control obligations. Demonstrate that failed replay remains inconclusive, an exact finite pass states its coverage, and numeric evidence cannot establish a symbolic dependent conclusion. Document each new operation's actual domain and run examples against the real exports.

### B. Rational convolution kernels

Own kernel_domination.py. Expose check_kernel_domination for coefficientwise domination of two scalar rational generating functions over QQ, with a nonnegative integer tail start N. This implies domination after convolution against any coefficientwise nonnegative scalar input by linearity. Cancel the difference, retain the polynomial part, and normalize partial fractions to c/(1-r*z), where distinct r are positive rationals. The poles themselves are 1/r. Replay the rational identity and check every coefficient below N. Require the polynomial part to vanish from N onward or advance the prefix accordingly. For the tail take largest ratio R, nonzero leading amplitude a, and verify a >= sum(abs(c)*(r/R)^N for negative lower amplitudes). Then division by R^n proves the bound for every n >= N. Handle a zero difference and a finite polynomial explicitly. A negative coefficient gives an exact disproving index. An insufficient explicit cutoff yields an inconclusive result. With an automatic cutoff, dominance of the largest ratio guarantees termination for supported inputs. A negative dominant amplitude eventually gives an exact negative coefficient. Repeated, complex or unsupported poles are outside this routine. Test a mixed-sign accepted tail, an actual early violation, and a rejected bound or pole.

### C. Exact linear algebra and fixed-rate positive state certificates

Own positive_state.py, linear.py and linalg.py. Supply exact rational matrix nullspace and linear solve with specified rectangular and inconsistent behavior. For a closed system `Ax <= b`, replay the three exact Farkas conditions `y >= 0`, `y^T A = 0` and `y^T b < 0` to prove infeasibility. Extract a witness using exact elimination with row provenance, an exact feasibility routine or rational candidate replay. Never apply this rule unchanged to strict inequalities. For a nonnegative rational square matrix M and nonnegative rational fixed rate rho, seek w_i >= 1, M^T w <= rho*w. This establishes contraction of w^T x on x >= 0 at that fixed rate. The normalization is equivalent to strictly positive w by homogeneity. Expose check_positive_state for a supplied vector and find_positive_state for bounded or exact discovery. A validated separating multiplier disproves existence of this positive linear functional only. Test valid and perturbed vectors, an infeasible fixed rate with replayable multipliers, and rectangular solves with a nontrivial kernel.

### D. Finite jets and structural reductions

Own jets.py and reductions.py. Represent finitely indexed commuting partial derivatives by a field identifier and multi-index. Enforce dimension, nonnegative indices, symbol freshness and coefficient domain. total_derivative acts by the chain rule on explicit coordinates and increments jet indices, and treats declared parameters as constants. For two scales, use independent x and y indices and D_i = partial_x_i + epsilon^(-1) partial_y_i, with epsilon explicitly invertible. check_jet_identity expands the requested finite derivatives then reduces the residual modulo the caller's supplied finite algebraic relations by exact Groebner remainder. If denominators are cleared, only invert declared nonzero factors. The guarantee is ideal membership in the localized or cleared polynomial ring. A nonzero remainder leaves the analytic claim unresolved. Test commuting mixed derivatives, explicit coordinate terms, relation reduction, and a nonzero residual.

Implement explicit reductions with a verifiable equality or a clearly stated conditional implication. For Gram, expand inner products of finite rational linear combinations into symmetric pairs using the existing Gram conventions. For a self-adjoint operator, reduce a scalar polynomial quadratic form to its scalar spectral polynomial values under stated spectral support and nonnegative weights. An explicitly supplied finite set is the support assumption. A general interval needs a scalar certificate for the whole interval. Supply small rational examples and ensure symmetry or support assumptions are visible.

### E. Polynomial times exponential

Own exp_series.py. Expose check_exp_series(P,Q,...) on univariate exact rational polynomials and the domain x >= 0. The normalized Taylor coefficient n! [x^n](P exp(x)+Q) is H(n)+n! q_n where H(t)=sum p_j (t)_j is a falling-factorial polynomial. Choose N > deg Q. Replay coefficients up to N-1 exactly. Prove H(n) >= 0 for all integers n >= N, for example with nonnegative forward differences at N via Newton's binomial expansion, or with a replayable exact integer sign decomposition. This sufficient certificate and absolute convergence on x >= 0 imply the claim. An automatic cutoff decides the Taylor coefficient condition. A negative higher-order Taylor coefficient leaves function positivity unresolved. A negative constant term disproves the claim at `x=0`. Test an example needing the integer tail and an everywhere nonnegative function with a negative Taylor coefficient such as (x-1)^2, represented with P=0.

### F. Bounded certificate discovery and recurrence realization

Own search.py and realization.py. Implement bounded geometric-series and polynomial/SOS searches with explicit finite candidate bases or degree/support budgets. Derive rational candidate coefficients, or enumerate within a stated finite budget, and replay every accepted candidate using verify_series_certificate or verify_polynomial_certificate. Budget exhaustion is inconclusive. Existing search_gram_certificate stays compatible. Test a recovered multi-term witness, failed bounds, and tampered replay. Implement recurrence-to-series for a finite rational constant-coefficient scalar recurrence with supplied initial terms. For s_n=sum a_j s_(n-j) from n=d onward, use denominator 1-sum a_j z^j and numerator equal to the first d coefficients of this denominator times the initial polynomial. Verify via exact multiplication and test nontrivial initial terms and degenerate coefficients. This realizes a formal series. Analytic convergence and positivity require separate arguments.

## Release gate and follow-ups

Run the baseline suite and new tests, with exact paths usable without CVXPY. Validate invalid input, rejection paths, finite scope, and evidence strength. Keep all public examples independently constructed from simple rational data. Package and test only public source. Defer differential ideal completion, mixed-sign or repeated-pole asymptotics beyond the certified fragment, rate optimization, interval spectral synthesis, general exponential inequalities and unrestricted SOS discovery to separate research work. Each would need its own input contract and mathematical justification.
